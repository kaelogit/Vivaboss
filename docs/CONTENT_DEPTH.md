# Content depth standard — Vivaboss Fusion

**Non-negotiable:** marketing pages and homepage sections must be **real deals**, not thin stubs that look unfinished on a client walkthrough.

This is locked now so we don’t “finish” a page with a headline + two sentences and call it done.

---

## What “real deal” means

Each public content surface should feel like a finished brand page:

| Must have | Notes |
|---|---|
| Clear purpose | One job per section |
| Enough copy | Enough to sell trust — not a telegram |
| Visual atmosphere | Real photos when available; intentional composition until then |
| Useful CTAs | Shop / book / WhatsApp / contact — not dead ends |
| Mobile polish | Same standard as desktop |
| Quality bar | Would still impress beside T40 + Lee |

Thin “SectionIntro + one paragraph + Coming soon” is **not** launch content. Scaffolding is fine **only** while marked as temporary in the plan — never as the final page.

---

## Pages that must be full builds (when we reach them)

### Homepage (`/`)
Not a path chooser and stop. Full experience (T40 / Lee Lagos density):

1. Brand-first hero (full-bleed visual plane)  
2. Announcement + promise strip  
3. Image-led path chooser (Shop / Services / Courier)  
4. Immersive shop mosaic by collection  
5. Featured product rail  
6. Fashion spotlight band  
7. Personalised deep split  
8. Services gallery + how-it-works  
9. Smart home buy × install cross-sell  
10. Courier vertical mosaic + care strip  
11. Interactive need finder  
12. Brand / craft story split  
13. Trust pillars  
14. Closing CTA  

Each section: one purpose, real copy length, intentional motion.

### About (`/about`)
Brand story, arms of the business, craft/culture, UK coverage, how to work with Vivaboss — with room for photography. Not three short paragraphs.

### Services hub + arms (`/services`, `/home`, `/smart-home`)
Already have service lists — deepen with how it works, coverage, install cross-sell, FAQs, booking CTAs. Booking forms become real in the bookings step.

### Courier (`/courier`)
Verticals + how booking works + care standards + UK-wide promise + book CTA. Not overview-only forever.

### Contact (`/contact`)
Real form + live phone/WhatsApp/email/address + map or area note when details arrive.

### FAQ / Privacy / Terms
FAQ: substantial, CMS-ready. Legal: proper policies before go-live (client/lawyer copy).

### Shop empty / category / PDP
Catalogue is data-driven. Empty states must be honest and branded — never fake non-clickable products.

---

## Scaffold vs finished

| State | Allowed? |
|---|---|
| Route exists with honest “next step” note | Yes, during build |
| Short page shipped as “done” | **No** |
| Homepage with only hero + path chooser at launch | **No** |
| About as a stub at launch | **No** |

When a content page is in the current step, deepen it to real-deal quality in that same step — don’t leave it for “later polish” if it’s customer-facing.

---

## Client assets still required for final polish

- Logo  
- Real photos (fashion, engraving, installs, courier)  
- Phone / WhatsApp / email / address  
- Shipping rates  
- Any legal copy preferences  

Until then: strong written structure + intentional placeholders — never sparse pages pretending to be finished.
